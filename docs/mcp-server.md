# MCP Server Integration

The QA Agent now exposes an MCP (Model Context Protocol) server, allowing it to be used as a testing tool from any MCP-compatible client such as **Claude Desktop**, **VS Code**, or custom clients.

## Quick Start

### 1. Start the MCP server

```bash
bun run mcp-server
```

The server communicates over **stdio transport** (JSON-RPC 2.0).

### 2. Register in Claude Desktop

Add the following to your `claude_desktop_config.json`:

**macOS:** `~/Library/Application Support/Claude/claude_desktop_config.json`

**Windows:** `%APPDATA%\\Claude\\claude_desktop_config.json`

```json
{
  "mcpServers": {
    "qa-agent": {
      "command": "bun",
      "args": ["run", "mcp-server"],
      "cwd": "/home/crislerwintler/projects/qa-agent",
      "env": {
        "GOOGLE_AI_STUDIO_API_KEY": "your-api-key-here"
      }
    }
  }
}
```

### 3. Register in VS Code

Add to `.vscode/mcp.json` in your workspace:

```json
{
  "servers": {
    "qa-agent": {
      "command": "bun",
      "args": ["run", "mcp-server"],
      "env": {
        "GOOGLE_AI_STUDIO_API_KEY": "your-api-key-here"
      }
    }
  }
}
```

## Available Tools

| Tool                  | Description                                              |
|-----------------------|----------------------------------------------------------|
| `run_exploratory_test` | Start an autonomous exploratory test on a given URL       |
| `run_single_page_test`| (Placeholder) Run a focused single-page test               |
| `get_test_status`     | Get real-time status of an active test session            |
| `stop_test`           | Gracefully stop a running test and save results           |
| `list_sessions`       | List all sessions (active + persisted in SQLite)         |

## Available Resources

| Resource                  | Description                                              |
|---------------------------|----------------------------------------------------------|
| `test-report://{sessionId}` | Read a markdown test report for the given session         |
| `test-report://latest`     | Read the most recent test report                          |

## Architecture

```
MCP Client (Claude / VS Code / Cursor)
    |
    |  JSON-RPC 2.0 over stdio
    v
src/mcp/server.ts          -- MCP Server instance
    ├── src/mcp/tools/exploratory.ts    -- run_exploratory_test
    ├── src/mcp/tools/status.ts         -- get_test_status, stop_test
    ├── src/mcp/tools/sessions.ts      -- list_sessions
    └── src/mcp/resources/reports.ts  -- test-report:// handler
    |
    v
src/agents/exploratory.ts  -- ExploratoryAgent (Playwright + LLM)
src/repositories/session.repository.ts -- SQLite persistence
```

## How the MCP server works

1. When a client connects, it sends an `initialize` request.
2. The server advertises capabilities: `tools` + `resources`.
3. Clients call `tools/list` to discover available testing tools.
4. Clients invoke tools with `tools/call` (e.g., `run_exploratory_test`).
5. The test runs **in a background task** so the tool call returns immediately with a `sessionId`.
6. Clients poll `get_test_status` to monitor progress.
7. Clients can `stop_test` to end exploration early.
8. Once stopped or completed, test reports are accessible via `test-report://` resources.

## Troubleshooting

### "bun: command not found"

Ensure Bun is on PATH:

```bash
export PATH="$HOME/.bun/bin:$PATH"
```

### "Report not found for session X"

Reports are generated by `generateReport()` and saved to `reports/report-{sessionId}.md`. If a report is missing, check the `reports/` directory or wait for the test to finish.

### Timeouts during long tests

The MCP protocol has no built-in timeout for tool calls, but some clients may apply their own. Use `get_test_status` to poll progress instead of waiting on tool calls directly.
