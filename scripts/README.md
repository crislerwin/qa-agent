# Database Migration Scripts

This folder contains scripts for managing database migrations with Drizzle ORM.

## Migration Script

### `run-migrations.ts`

This script automatically checks if database tables exist and runs Drizzle migrations if needed.

**Features:**
- ✅ Checks if required tables exist
- ✅ Runs migrations only when needed
- ✅ Verifies pgvector extension is installed
- ✅ Safe to run multiple times (idempotent)

**Usage:**

```bash
# Run migrations manually
bun run db:migrate

# Or run the script directly
bun run scripts/run-migrations.ts
```

**Docker Usage:**

The migration script runs automatically when the Docker container starts via the `docker-entrypoint.sh` script.

**How it works:**

1. Connects to the database using `DATABASE_URL`
2. Checks if tables (`conversations`, `messages`, `documents`) exist
3. If tables are missing, runs Drizzle migrations from the `drizzle/` folder
4. Verifies pgvector extension is installed
5. Exits with success if everything is ready

**Environment Variables:**

```bash
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/agents_db
```

## Docker Entrypoint

### `docker-entrypoint.sh`

This script runs when the Docker container starts and handles:

1. **Database Connection** - Waits for PostgreSQL to be ready
2. **pgvector Extension** - Ensures the extension is enabled
3. **Drizzle Migrations** - Runs database migrations
4. **API Server** - Starts the application

**Startup Flow:**

```
Container Start
  ↓
Wait for Database (up to 60 seconds)
  ↓
Enable pgvector Extension (docker/init-db.sql)
  ↓
Run Drizzle Migrations (scripts/run-migrations.ts)
  ↓
Start API Server (server.js)
```

## Migration Files

Migrations are stored in the `drizzle/` folder and are auto-generated by Drizzle Kit:

```bash
drizzle/
├── 0000_powerful_payback.sql   # Initial schema migration
└── meta/
    ├── 0000_snapshot.json      # Schema snapshot
    └── _journal.json           # Migration history
```

## Creating New Migrations

When you modify the database schema in `src/db/schema.ts`:

1. Generate a new migration:
   ```bash
   bun run db:generate
   ```

2. Review the generated SQL in `drizzle/XXXX_*.sql`

3. Apply the migration:
   ```bash
   bun run db:migrate
   ```

4. For development, you can push directly without migrations:
   ```bash
   bun run db:push
   ```

## Troubleshooting

### Migration Failed

If migrations fail:

1. Check database connection:
   ```bash
   psql $DATABASE_URL -c "SELECT 1;"
   ```

2. Verify pgvector extension:
   ```bash
   psql $DATABASE_URL -c "SELECT * FROM pg_extension WHERE extname = 'vector';"
   ```

3. Check migration files exist:
   ```bash
   ls -la drizzle/
   ```

### Tables Already Exist

The migration script is smart and won't re-run migrations if tables already exist. This is normal and safe.

### Fresh Database Setup

For a completely fresh database:

1. Stop containers:
   ```bash
   docker-compose down -v
   ```

2. Start containers (migrations run automatically):
   ```bash
   docker-compose up -d
   ```

3. Check logs:
   ```bash
   docker-compose logs -f api
   ```

## Production Deployment

For production, migrations should be run as part of your deployment process:

1. **Pre-deployment**: Generate migrations from schema changes
2. **Deployment**: Apply migrations before starting new app version
3. **Rollback**: Keep migration history for safe rollbacks

The `run-migrations.ts` script is production-ready and safe to use in CI/CD pipelines.
